# Changelog

## 0.1.3 — 2026-11-03

### Fixed

- **Mods that use a top-level `return` could not run at all.** Upstream D2RMM evaluates each
  mod as `(function(){ const config = …; <mod code> })()`, which is what makes the common
  guard `if (D2RMM.getVersion() < 1.5) { D2RMM.error(…); return; }` legal. D2rlmm evaluated
  the file as a global script, so those mods died with
  `SyntaxError: return not in a function` before running a line
  (ExpandedStash, ExpandedInventory, TerrorZoneCustomizer in one real library). The wrapper
  is now applied, with the opening brace on line 1 so error line numbers still match the mod.

### Changed

- **The header button now knows whether it has anything to do.** It records what it installed
  (`installed.json`, resolved config included) and compares that with the current selection:
  `Apply changes (N)` when the game differs from the list, `Installed (N)` when it matches,
  `Uninstall` when nothing is enabled. Previously it said `Install (N)` in every case, so
  unticking a mod looked like it did nothing — the list is a staging area, and nothing said so.
  (Upstream makes the same distinction by switching its button between outlined and filled.)

## 0.1.2 — 2026-11-03

### Fixed

- **A large mod could abort with `Exception generated by quickjs: Null"null"`.** The
  sandbox capped each mod's JavaScript heap at 512 MB, and a mod that caches every file
  it touches until its final flush needs several hundred MB on its own — wayfinding act3
  died two thirds of the way through with no usable message. The cap is now 4 GB and
  overridable with `D2RLMM_JS_MEMORY_MB=<megabytes>`.
- **That failure now explains itself.** A caught `null`/`undefined` exception is reported
  as "the mod stopped without reporting an error — the JavaScript sandbox most likely hit
  its N MB memory limit (heap in use: M MB)" instead of the raw `Null"null"`. Non-Error
  values are printed as a value rather than swallowed.

## 0.1.1 — 2026-11-02

### Fixed

- **Uninstall.** With nothing enabled the Install button becomes **Uninstall** and removes
  the install: it deletes the generated mod folder, or in direct mode restores every file
  the mods changed and deletes the ones they created. Before this, the button was disabled
  with no mods enabled, so an install could not be removed from the app at all.
- **Direct mode left a switched-off mod's files behind.** The data folder kept whatever the
  last install wrote, so unticking a mod and installing again still shipped its edits. The
  install now records the files it wrote (`direct-install.json` in the state dir) and puts
  back anything the current mod set no longer produces — including files from mods that
  have since been deleted from the library.
- Reverting creates parent folders before restoring a file, so a revert no longer fails with
  `No such file or directory` on a tree a mod had replaced.

### Changed

- Menu: "Revert to vanilla (direct mode)" is now "Uninstall mods (restore vanilla)", and it
  works in both modes.
- `d2rlmm-cli uninstall` added (`--dry-run` on `install` still does the same thing).

## 0.1.0 — 2026-11-02

First release.

### Mod engine

- Runs unmodified D2RMM `mod.js` mods in an embedded QuickJS sandbox, with the
  `D2RMM` API at upstream version 1.9.
- Full `mod.json` config schema: `checkbox`, `number`, `text`, `select`, `color`,
  `section`, plus `visible` / `overrideValue` / `defaultValue` bindings.
- TSV and JSON game data read-modify-write, with the same carriage-return handling
  as upstream and JavaScript-style value coercion on write.
- Installs claim nothing until every mod has run: a failure leaves the previous
  install untouched, and a run where every mod fails does not delete it either.
- Mod-conflict warnings when one mod overwrites another's file without reading it.
- Install order is the merge order; reordering rebuilds the set.

### Install targets

- **Mod folder** (default): `mods/<Name>/<Name>.mpq/data` plus `modinfo.json`, the
  layout `-mod <Name> -txt` loads.
- **Data folder** (`-direct`): writes into the game's `data` folder, or any data
  folder you choose — including a tree extracted by Cairn or D2R File Extractor.
- Vanilla data can come from the game's own CASC archives or from an extracted data
  folder, so the app works on a machine whose archives cannot be read.

### Interface

- GTK4 / libadwaita, GNOME 50 runtime.
- Mod list with enable switches, ordering, per-mod configure dialogs generated from
  each mod's schema, and install progress.
- Mod import from `.zip` (either archive layout) or from a folder.
- Install log viewer, and a **Save error report** action that writes the log plus
  environment, mod list and versions to a single file.
- No game-launch feature by design; the correct launch options are shown with a copy
  button, and shown differently for each install target.

### Command line

- `d2rlmm-cli list | install | version` for headless installs and scripting.

### Packaging

- Flatpak `io.github.corngoblin.D2rlmm` on `org.gnome.Platform//50`, bundle attached to
  the release as `io.github.corngoblin.D2rlmm.flatpak` (version-free filename).
- Icon shipped as SVG plus 64/128/256/512 px PNGs, in the Diablo II palette.

### Known limitations

- TypeScript mods (`mod.ts`) are not run; they are reported clearly.
- `D2RMM.extractSprite` is not implemented.
- No Nexus Mods integration and no save-file editor.
- The CASC reader is implemented but not yet exercised against a real game install;
  the extracted-data path is the verified one.
